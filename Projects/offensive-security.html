01 — OVERVIEW

Project Overview

This project documents a controlled offensive-security assessment performed against intentionally vulnerable systems inside a personally managed VirtualBox environment.

The engagement began with preparation of the Kali Linux attacker workstation, network validation, and reconnaissance tool verification. I then identified the target system, mapped its exposed services, researched potential weaknesses, and selected findings for validation.

Controlled exploitation of vulnerable FTP and Samba services confirmed remote command execution and root-level access. Findings were documented with evidence, impact, severity, and practical mitigation recommendations rather than presenting scan output alone.

STEP 02

Network Discovery

I verified connectivity between Kali Linux and the Metasploitable 2 target at 192.168.56.101.

After confirming the target was reachable, I ran an initial Nmap scan to identify exposed services and establish the available attack surface.

Command

nmap 192.168.56.101

Initial Nmap reconnaissance identified the target's exposed TCP services.

STEP 03

Service & Version Enumeration

I performed service and version detection to collect additional information about the software running on the target.

The scan identified numerous legacy and exposed services, including FTP, SSH, Telnet, Samba, MySQL, PostgreSQL, VNC, and web services.

FTP on TCP port 21 was identified as vsftpd 2.3.4, making it a candidate for focused vulnerability research and validation.

Command

nmap -sV 192.168.56.101 -oN service_scan.txt

Service-version detection identified legacy software and potential attack paths for further investigation.

STEP 04

Detailed Enumeration

I performed a more detailed Nmap scan to gather operating-system context, service configuration details, and additional information about exposed applications.

The results confirmed an older Linux environment with numerous remotely accessible services. This evidence helped prioritize services for validation rather than treating every open port as a confirmed vulnerability.

Command

nmap -A 192.168.56.101 -oN detailed_scan.txt

Detailed enumeration provided operating-system and application context used to prioritize testing.

STEP 05

VSFTPD Vulnerability Validation

Based on the enumeration evidence, I selected the FTP service running vsftpd 2.3.4 for controlled validation with Metasploit.

I configured the VSFTPD backdoor module with the target and listener addresses, then reviewed the options before execution.

Metasploit Module

use exploit/unix/ftp/vsftpd_234_backdoor
set RHOSTS 192.168.56.101
set LHOST 192.168.56.102
show options

The VSFTPD module was configured and reviewed before controlled execution.

STEP 06

Successful Exploitation & Privilege Validation

Executing the VSFTPD module successfully triggered the vulnerable service and established a remote session.

I opened a shell and used whoami to verify the privilege level. The command returned root, confirming administrative-level access.

Listing the root filesystem further validated interactive command execution and control of the target host.

STEP 07

Samba Remote Command Execution Validation

I continued reviewing the attack surface and selected the exposed Samba service for additional testing.

The Metasploit user_map_script module successfully established a remote command shell on the target.

Running whoami returned root, confirming privileged remote command execution through a second independent attack path.

05 — FINDINGS

Key Findings

FINDING 01

VSFTPD 2.3.4 Backdoor

CRITICAL

Enumeration identified FTP running vsftpd 2.3.4 on TCP port 21. Controlled testing confirmed unauthorized remote access and root-level command execution.

Evidence

Metasploit established a remote session, and shell validation returned root.

Impact

Successful exploitation may allow complete system compromise, data access, modification, persistence, and further attacks.

Mitigation

Remove the vulnerable release, install a supported version from a trusted source, disable unnecessary FTP, and restrict network access.

FINDING 02

Excessive Exposed Network Services

HIGH

Enumeration identified more than 20 exposed TCP services, including legacy protocols, databases, remote-access services, and multiple application interfaces.

Evidence

Nmap exposed a broad set of services available for remote interaction.

Impact

A large attack surface increases the likelihood of exploitable software, weak configurations, and unnecessary access paths.

Mitigation

Disable unnecessary services, restrict required ports with firewalls, segment sensitive services, and follow least-functionality principles.

FINDING 03

Samba Remote Command Execution

CRITICAL

Controlled testing confirmed the Samba service could be abused to establish a remote command shell with root privileges.

Evidence

The usermap_script module established a remote shell, and whoami returned root.

Impact

Remote root execution may allow full system control, data compromise, tool deployment, and use of the host for further attacks.

Mitigation

Replace unsupported Samba versions, restrict SMB to trusted systems, disable unnecessary services, and segment administrative protocols.

08 — LESSONS LEARNED

Lessons Learned & Project Takeaways

The assessment reinforced that effective penetration testing depends on disciplined progression from discovery to evidence gathering, targeted validation, and clear reporting.

01 — PREPARATION

Validate the Platform First

Network and tool validation reduced uncertainty before testing began.

02 — ENUMERATION

Open Ports Are Starting Points

Version and configuration context are required before selecting an attack path.

03 — VALIDATION

Evidence Matters More Than Assumptions

Controlled testing distinguished exploitable weaknesses from general attack-surface observations.

04 — ACCESS

Verify the Result

Session establishment alone was not enough; command execution and privilege level were validated.

05 — SCOPE

Controlled Environments Enable Safe Practice

All testing remained within intentionally vulnerable, personally controlled systems.

06 — REPORTING

Findings Must Support Remediation

Evidence and impact are most useful when paired with practical mitigation guidance.
